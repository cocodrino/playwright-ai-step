  <files>src/parallel.ts, src/ai.ts (add batch function)</files>
  <action>
    Create `src/parallel.ts`:
    
    ```typescript
    import { ai } from './ai'
    import type { AiOptions } from './types'
    
    interface ParallelResult {
      instruction: string
      result: boolean | string | number
      error?: string
      durationMs: number
    }
    
    /**
     * Execute multiple ai() calls in parallel.
     * Useful for batch operations or running independent assertions.
     * 
     * maxConcurrency: how many LLM calls at once (default: 3)
     * 
     * Note: DOM is serialized fresh for each call.
     */
    async function aiParallel(
      instructions: string[],
      options: AiOptions,
      maxConcurrency = 3
    ): Promise<ParallelResult[]>
    ```
    
    Implementation:
    - Use a semaphore pattern (simple async queue) to limit concurrency
    - For each instruction, call serializePage() + ai() independently
    - Collect results and return
    - Handle errors gracefully — one failure doesn't cancel others
    
    Example use:
    ```typescript
    const results = await aiParallel([
      'assert the header is visible',
      'assert the sidebar is visible',
      'assert the footer is visible',
    ], { page })
    // All 3 run concurrently — much faster than sequential
    ```
  </action>
  <verify>aiParallel runs 3 instructions concurrently; no LLM errors cross-contaminate</verify>
  <done>Parallel ai() execution working with configurable concurrency</done>
</task>

  <name>Task 4: Self-healing CLI tool</name>
  <files>src/cli.ts, src/healer.ts</files>
  <action>
    Create `src/cli.ts` — the main CLI entry point:
    
    ```bash

    npx playwright-ai-step generate "book a flight on delta.com"
    
    # Run in self-healing mode

    ```
    
    Create `src/healer.ts`:
    
    ```typescript
    /**
     * Self-healing: when a test fails due to selector not found,
     * automatically retry with a revised prompt to the LLM.
     * 
     * Use the failed selector info + DOM snapshot + error message
     * → ask LLM to suggest a better selector
     * → retry the test step
     * 
     * This is Phase 5's "advanced self-healing" beyond Phase 3's retry.
     */
    async function healFailedStep(
      originalInstruction: string,
      failedCommand: LLMCommand,
      errorMessage: string,
      snapshot: DOMSnapshot,
      config: LLMConfig
    ): Promise<LLMCommand>
    ```
    
    The heal prompt includes:
    - The original instruction
    - The failed selector + error
    - The full DOM snapshot
    - "Here is the page. What is the correct way to accomplish the original instruction?"
    
    This is different from Phase 3's simple retry — it re-interprets the instruction
    with full error context and may suggest a different action entirely.
  </action>
  <verify>CLI entry point compiles; healer function exists</verify>
