# Fix: `first.url` is null in extract mode — href attributes not sent to LLM

## Root Cause

**`buildExtractUserMessage()` in `src/llm-client.ts` (lines 121-158) does NOT include `href` or other URL-relevant attributes** when serializing DOM elements for the LLM.

The element list sent to the LLM looks like this:
```
[link] <a> "TypeScript in 100 Seconds"
[link] <a> "Learn TypeScript – Crash Course for Beginners"
```

But the actual URLs (`/watch?v=zQnBQ4tB3ZA&pp=...`) stored in the `href` attributes are **never included**. The `buildExtractUserMessage()` function only serializes: `role`, `tagName`, `id`, `dataTestId`, `textContent`, `placeholder`, `ariaLabel`.

The DOM serializer (`dom-serializer.ts`) correctly captures `href` in the `attributes` field (line 16: `'href'` is in `ALLOWED_ATTRS`), and it IS present in the `ElementDescriptor.attributes` object. But `buildExtractUserMessage()` simply ignores `attributes` entirely.

As a result:
- The LLM is asked to extract URLs from video results
- The LLM has NO URL data available in the prompt
- The LLM either returns `null` or fabricates URLs
- Test assertion `expect(first.url).toContain("youtube.com/watch")` fails because `null` doesn't contain anything

**The same issue exists in `buildUserMessage()`** (standard mode), but it's less impactful there since Playwright's selector resolution doesn't rely on LLM-returned URLs.

### Secondary issue: relative URLs

YouTube uses relative URLs (`/watch?v=...`), but the EXTRACT_SYSTEM_PROMPT instructs: "For URLs: always return the complete watch/share URL (https://www.youtube.com/watch?v=...)". Even if we include `href` data, the LLM would see `/watch?v=...` and would need to reconstruct full URLs. We should resolve relative URLs to absolute ones before sending to the LLM.

## Fix Plan

### 1. Include attributes in element serialization for extract mode

**File**: `src/llm-client.ts`, function `buildExtractUserMessage()` (line ~127-141)

Add `href`, `src`, `alt`, and `title` attributes to the element serialization. Currently the mapping only includes:
```ts
if (el.role && el.role !== el.tagName) parts.push(`[${el.role}]`)
if (el.tagName) parts.push(`<${el.tagName}>`)
if (el.id) parts.push(`#${el.id}`)
if (el.dataTestId) parts.push(`[data-testid="${el.dataTestId}"]`)
if (el.textContent) parts.push(`"${el.textContent}"`)
if (el.placeholder) parts.push(`placeholder="${el.placeholder}"`)
if (el.ariaLabel) parts.push(`aria="${el.ariaLabel}"`)
```

It should also include key attributes:
```ts
// Add href for links, src for images, etc.
if (el.attributes?.href) parts.push(`href="${el.attributes.href}"`)
if (el.attributes?.src) parts.push(`src="${el.attributes.src}"`)
```

### 2. Resolve relative URLs to absolute in the DOM serializer

**File**: `src/dom-serializer.ts`, inside `page.evaluate()` block (line ~55-91)

When capturing `attributes`, resolve `href` values to absolute URLs. This can be done by using `el.href` (which returns absolute URLs on anchor elements) instead of `el.getAttribute('href')` (which returns the raw attribute value, which may be relative).

Change line ~72 from:
```ts
rawAttrs[a.name] = a.value
```
To special-case `href`:
```ts
if (a.name === 'href') {
  // Use absolute URL from anchor elements
  rawAttrs[a.name] = (el as HTMLAnchorElement).href || a.value
} else {
  rawAttrs[a.name] = a.value
}
```

Actually, a more robust approach is to use the element property instead of attribute for URLs:
```ts
if (a.name === 'href' && 'href' in el) {
  rawAttrs[a.name] = (el as any).href || a.value
} else {
  rawAttrs[a.name] = a.value  
}
```

### 3. Also include attributes in `buildUserMessage()` for consistency

**File**: `src/llm-client.ts`, function `buildUserMessage()` (line ~84-104)

Apply the same fix — include `href` and `src` in the standard mode element serialization for better LLM context.

## Files to modify

1. **`src/llm-client.ts`** — `buildExtractUserMessage()` and `buildUserMessage()`: Include `href`/`src` attributes from `el.attributes` in the element description
2. **`src/dom-serializer.ts`** — Resolve relative `href` values to absolute URLs using `el.href` property

## Verification

After the fix, re-run the failing test:
```bash
npx playwright test sample/youtube-search.spec.ts -g "extract structured video list" --reporter=list
```

The test should now pass because the LLM will receive href data like `href="https://www.youtube.com/watch?v=zQnBQ4tB3ZA"` and can properly extract full URLs.
